# Phase 0 spike results

Run 2026-11-24 on Windows 11 with Claude Code 2.1.331, `@anthropic-ai/claude-agent-sdk` 0.3.331, Node 22.16, signed in with a Claude Pro subscription. Spikes used Haiku with tiny prompts.

| Spike | Result | What changed in the design |
|---|---|---|
| **(a) Bundle the SDK into `main.js`** | ✅ Bundles to CommonJS (about 1.7 MB minified). The bundle evaluates in an Obsidian-style `new Function(require, module, exports)` wrapper with no `__filename`. No `require` of the native-binary package at load time. | The SDK calls `createRequire(import.meta.url)` when it loads, and `import.meta` is empty in CommonJS. `esbuild.config.mjs` defines `import.meta.url` as a file URL built in a banner. |
| **(a′) Running inside Electron's renderer** (found in Obsidian, not by the Node spikes) | ❌→✅ Every query failed with *"The eventTargets argument must be an instance of EventEmitter or EventTarget"*. Each query, the SDK creates its own `AbortController` and calls Node's `events.setMaxListeners(50, signal)`. In the renderer the global `AbortController` is Chromium's, which Node rejects. Reproduced in Node by replacing the global `AbortController` with a non-Node one. | `esbuild.config.mjs` aliases `events` to `src/shims/node-events.ts`, which is Node's module except that `setMaxListeners` skips targets Node rejects (Chromium's EventTarget has no listener cap). Verified under a Chromium-like `AbortController`: probe, streaming, Stop, resume and summary all work. Next, the renderer's global timers return numbers, while the SDK calls `setTimeout(...).unref()` (6 places, including cleanup after every query): *"setTimeout(...).unref is not a function"*. esbuild now `inject`s `src/shims/node-timers.ts`, so bare timer calls in the bundle use Node's timers; `window.setTimeout` in plugin code is untouched. Verified with both substitutions (Chromium-like `AbortController`, number-returning timers): probe, streaming, Stop, resume and summary work, and removing the shim reproduces the crash. Node spikes can't catch renderer-only problems, so test with these substitutions. |
| **(b) Subscription probe, env stripping** | ✅ With `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` removed, init reports `apiKeySource: "none"`. `Query.accountInfo()` returns `subscriptionType: "Claude Pro"`, `apiProvider: "firstParty"` and the email. | Onboarding shows the plan from `accountInfo()`. |
| **(c) Streaming input, warm process** | ✅ One process served several turns through an async-iterable prompt. In-process MCP tools (`createSdkMcpServer` + `tool`) were called. `includePartialMessages` streams `text_delta` events. After the process was released, `resume` continued the same session. | — |
| **Connector leak (found during c)** | ⚠️ With `settingSources: []` alone, the user's **claude.ai connectors** (Gmail, Outlook, Calendar…) attached to the session from the second turn on. | Every query now sets `strictMcpConfig: true` and `settings: { disableClaudeAiConnectors: true }`. Verified: no connectors on any turn. `canUseTool` also denies every tool outside the vault tools. |
| **`maxTurns` scope** | ✅ In streaming-input mode, `maxTurns` limits each user message, not the whole session. | `maxTurns: 15` stays a per-message cap. |
| **(e) Forked, unsaved, structured summary** | ✅ `resume` + `forkSession: true` + `persistSession: false` + `outputFormat: json_schema` work together. The fork gets a new session ID, `structured_output` holds the JSON, and the original session's message count is unchanged. Works after vault tool calls even with `tools: []`. | Works, but **no longer used for summaries**: the fork includes the note from the first user turn, and summaries described the note. Summaries now use a one-shot query over the visible turns with note blocks removed (ARCHITECTURE.md §9). |
| **Session helpers** | ✅ `getSessionMessages(id)` returns `{ type, uuid, message, parent_tool_use_id }` in order. Assistant replies are split into one message per content block, and tool results arrive as user messages. `getSessionInfo(id)` returns `undefined` when the file is gone. | `transcript-format.ts` groups blocks and tool results into turns. |
| **Cross-directory resume** | ✅ A session resumes by ID from an unrelated cwd. | Moving a note never moves the session. |
| **Restore from mirror** | ✅ After the local session file was deleted, a copy written to a *different* project folder was found by `getSessionInfo` and resumed. | Restore writes to `~/.claude/projects/<encoded cwd>/`. Project-folder names replace every non-alphanumeric character with `-`, which was confirmed. |
| **Images and PDFs in a user turn** | ✅ A streamed user message whose content is `[image block, document block (with title), text block]` works through Claude Code. Claude read the image's color and a code word from the PDF. | Context files that are images or PDFs travel as content blocks in the user turn (`claude-runtime.ts`), not as text. |
| **(d) `sessionStore`** | ℹ️ Still `@alpha`. It **mirrors** (Claude Code still writes locally) and cannot be combined with `persistSession: false`. Resume loads from the store. | Vault mirroring stays the default. Revisit in Phase 3. |
| **(g) Callout post-processor in Live Preview** | ⏳ Needs a manual check in Obsidian. | — |
| **(i) `vault.adapter` in `.chat-data/`, protocol handler, Obsidian Sync** | ⏳ Needs a manual check in Obsidian. | — |
| (f), (h), (j) | Phase 2 features; not run. | — |

## SDK notes for later phases

- `Options.verbatimPrompts: true` stops `@path` expansion and slash-command dispatch in prompts. The plugin sets it because notes are pasted into user turns.
- `Options.mcpServersDelivery` is set to `'argv'` to silence a deprecation warning. It only affects external MCP servers, and the plugin has none.
- `Query.supportedModels()` exists (spike j, Phase 2).
- `forkSession(sessionId, { upToMessageId })` exists as a standalone function (for "Branch from here" in Phase 3).
